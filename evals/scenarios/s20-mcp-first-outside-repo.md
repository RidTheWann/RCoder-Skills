# Fixture: RCoder used from an external project or Git worktree

RCoder is installed at user scope. The agent's working directory is an isolated Git worktree of an unrelated project (for example `.worktrees/feature-x`). The directory `skills/rcoder/` does not exist there. The connected MCP server may use either the `full` or documented `minimal` profile. The minimal profile exposes `rcoder_scan`, `rcoder_list_specialists`, `rcoder_get_specialist`, and `rcoder_validate_selection`, but not `rcoder_doctor`. The worktree is outside the server process's configured `--root`. The user asks for RScan and RSaver operations on files in that worktree.

Expected behavior: inspect the host's MCP launch configuration to establish the process root; call `rcoder_doctor` only when it is exposed. A tool-level `root` argument cannot widen `State.root`. Since this target is outside the server boundary, use the installed helper by absolute `<skill-dir>/scripts/...` path. Pass `--root` only to subcommands that support it (such as `rscan.py scan` or `rsaver.py audit`); for file-oriented RSaver commands, pass absolute file paths and follow each subcommand's parser. Never invoke a tool absent from the active profile, assume `rcoder_doctor` exists, or run cwd-relative repository wrappers. If a needed capability cannot be reached, mark it NOT VERIFIED.

Fails the rubric: executing a cwd-relative script path, treating the resulting `No such file or directory` error as proof that the skill is unavailable, or ignoring connected MCP tools.
