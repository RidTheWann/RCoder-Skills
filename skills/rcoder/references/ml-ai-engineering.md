# Machine learning and AI systems engineering

## Activate when
Model training/fine-tuning, inference serving, retrieval, evaluation, agent orchestration, or ML data pipelines. Use model-adaptation for how an agent should work, not for training or serving a model.

## Mission and expertise
Own reproducibility of data/model/artifact versions, leakage-free evaluation, joint quality-latency-cost measurement, and least-privilege agent tooling. Treat model output as untrusted data, never as policy or code.

## Mental model
ML behavior depends on data provenance, preprocessing, model/runtime version, inference configuration, evaluation design, and deployment drift. A benchmark result without pinned versions, splits, and confidence intervals is not evidence.

## Prerequisites and reconnaissance
1. Record dataset provenance/license, consent/PII constraints, preprocessing, splits, model revision, tokenizer, and evaluation protocol.
2. Determine how prompts, tool schemas, retrieval indexes, and model parameters are versioned.
3. Identify tool permissions and which actions require human approval.
4. Establish baseline quality, latency, throughput, memory, and cost before changes.

## Procedure
1. Record dataset provenance/license, consent/PII constraints, preprocessing, splits, model revision, tokenizer, and evaluation protocol.
2. Separate training, validation, test, and production data; prevent leakage and duplicate contamination.
3. Use task-relevant baselines and confidence intervals; report quality, latency, throughput, memory, and cost together.
4. Version prompts, tool schemas, retrieval indexes, model parameters, and evaluation fixtures.
5. Enforce tool permissions, output validation, secret isolation, prompt-injection defenses, and approval for consequential actions.
6. Monitor drift, failure clusters, abuse, and rollback triggers after deployment.

## Decision tree
- Evaluation set overlaps tuning examples → rebuild splits and deduplicate before reporting results.
- Model output drives a tool call → validate the call against a schema and permissions before execution.
- Consequential action → require explicit approval or a deterministic policy check, not model judgment alone.
- Untrusted content enters a prompt → delimit it as data and defend against prompt injection.
- Latency or cost increased → measure quality jointly; do not optimize one in isolation.
- Retrieval results stale → version the index and define refresh/rebuild triggers.
- Claim of improvement → require a pinned comparison with confidence intervals and retained artifacts.

## Tool strategy
Use pinned data/version tooling, evaluation harnesses, deterministic fixtures, adversarial tests, and load/cost measurement. Verify model and runtime identifiers from configuration. Never log sensitive content by default and never paste secrets into prompts.

## Advanced techniques
- **Leakage checks:** deduplicate across splits and verify no test data influenced preprocessing choices.
- **Prompt/tool versioning:** treat prompts and tool schemas as release artifacts with diffs and evaluation records.
- **Ablation discipline:** hold constant model, settings, tools, permissions, fixture, prompt, and rubric when comparing variants.
- **Adversarial evaluation:** include injection, malicious tool output, and malformed data in the suite.
- **Joint dashboards:** report quality, latency, cost, and failure clusters side by side to prevent misleading gains.

## Failure modes
- **Treating model output as trusted code or policy** → unauthorized actions → validate and gate.
- **Evaluating only on prompt-tuning examples** → inflated results → held-out fixtures.
- **Logging sensitive inference content** → privacy breach → redact and minimize.
- **Unbounded tool access** → security failure → least privilege and approvals.
- **Unpinned model revision** → irreproducible results → record exact identifiers.

## Quality checklist
Data/model/prompt versions are reproducible; evaluation avoids leakage and cherry-picking; agent tools are least-privileged and validated; latency, quality, and cost are jointly measured.

## Anti-patterns
Accepting a model's claim that a test passed; running untrusted code generated by a model without review; reporting a single-run score; ignoring confidence intervals; deploying without rollback triggers.

## Verification
Run deterministic data checks, baseline/regression evaluation, adversarial tests, load/cost tests, and staged rollout checks. Record exact configuration and results; mark unmeasured conditions NOT VERIFIED.

## Output format
Artifact versions · data constraints · evaluation metrics · tool permissions · deployment risks.
